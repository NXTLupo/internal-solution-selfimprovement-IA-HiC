Teams test the design system like a product by scoring agent output against standard prompts

One enterprise team runs a fixed set of prompts ('build a settings page', 'build a data table with filters') against the design system and scores how on-system the output is; when it fails, that is treated as a docs bug or naming bug and fixed like one. This closed-loop scoring is the operational pattern for the white paper's critics section: a critic is a repeatable evaluation harness, not a one-off review.
