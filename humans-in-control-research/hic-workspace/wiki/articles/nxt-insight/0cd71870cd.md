Comparative 'when to use this instead of that' guidance is what stops lookalike-component drift

Practitioners find property tables tell an agent what a component can do but never which of three lookalike components is right, which is the source of 80%-right, off-system screens. Writing 'when not to use this' and 'use this instead of a similar one' into component docs fixed it. This decision-guidance layer is a specific, implementable requirement for the white paper's skills and critics sections.

Property tables tell an agent what a component can do. They never tell it which of three lookalike components is the right one. Comparative guidance is what fixed it for me.
