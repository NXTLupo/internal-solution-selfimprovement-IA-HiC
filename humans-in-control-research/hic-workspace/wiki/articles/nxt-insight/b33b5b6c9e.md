Idempotent, guarded state writes make agent tool-calls safe to retry

Databricks documents an execution contract where each record carries a stable identity (run_id, tool_call_id, review_id, decision_id) and Postgres primary keys enforce them, so a retry targets the same tool_call_id and a terminal-state guard prevents double-commit. Every side-effecting tool needs an equivalent contract; the orchestrator determines when to retry, the activity determines how the external system handles it. This is the reliability substrate the white paper's harnessed-execution and hooks sections must specify.

Deterministic IDs make retries converge on the same logical row, while each guarded write defines which state transitions are legal.
