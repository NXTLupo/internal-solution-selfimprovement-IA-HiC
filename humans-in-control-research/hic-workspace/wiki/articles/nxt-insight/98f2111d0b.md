Exposing raw developer APIs through MCP breaks agents; task-level tools are the fix

Webflow's engineering account explains why early MCP implementations that exposed developer APIs directly (getPages, updateContent, publishPage) fail: every extra tool call increases latency, token consumption, context pressure, and failure probability as the agent preserves identifiers, disambiguates results, and sequences dependent operations. The fix is declarative task-level tools that turn multi-step workflows into a single intent-driven call, letting the platform handle orchestration. But task-oriented design creates tool explosion at scale, pushing toward a layered tool architecture. This is directly instructive for how Figma's MCP surface should be shaped for reliable harnessed execution.

Declarative APIs turn complex, multi-step workflows into a single intent-driven call... This reduces failure modes and lets the agent focus on the user’s goal instead of execution details.
