Code-to-canvas capture surfaces the edge states that only appear once a feature hits real data

Figma's workflow lab shows that as an export flow evolves in code, states like encoding errors, render status, empty selections, and unsupported-format edge cases emerge that were not missed but became clear once the feature hit real code and data. Bringing production states back onto the canvas via MCP lets designers shape what actually ships. For email automation this predicts the same class of edge states, such as unsupported client rendering or empty personalization tokens, that a validation agent must catch.

These aren't states the designer missed or forgot to design; they're issues that became clear once the feature hit real code and data. [articles/figma-blog/cb124012b5.md#c1]
