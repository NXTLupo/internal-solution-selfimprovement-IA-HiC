Agent-ready surfaces must be redesigned around intents, not wrapped developer APIs

Webflow reports that wrapping existing developer APIs as MCP tools failed because agents don't read docs, manage state, or compose granular endpoints the way developers do, producing chatty, low-level tools that failed on complex workflows. Over a year Webflow redesigned tools around intents instead of endpoints, simplified schemas, and made responses easier for agents to reason about. This is a direct blueprint for how Figma's MCP tools must be shaped for reliable agentic workflows.

APIs designed for developers don't work well for agents... directly exposing Developer APIs to agents made our early MCP tools too low-level and overly chatty [articles/webflow-blog/e1de51618d.md#c1]
