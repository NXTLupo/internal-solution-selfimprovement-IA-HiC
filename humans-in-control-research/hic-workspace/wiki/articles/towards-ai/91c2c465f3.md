Six parts cover the code around the model, and two cover team work outside it.

_This is Part 2 of eight. Which tools the model gets, and how it finds the rest._

*   **Part 1**: [Make Your AI Agent Recover When a Tool Call Fails](https://medium.com/towards-artificial-intelligence/make-your-ai-agent-recover-when-a-tool-call-fails-fd4d038c1dce)

Part 1 was about the loop and what the model reads back. An agent is a model inside a harness, the code around the model, and the harness decides what the model reads after each tool call and when the run ends. If your team does not design that code, your framework’s defaults do, and an upgrade can change them without you knowing. Part 1 also set out a design review that works with any model or framework: one main pattern and one anti-pattern for each part in the map above.

This part is about the step before a tool call: which tools the model gets. The model can only call a tool that is in its request, and it picks one by its name, description and arguments. Four things can decide what goes into that request: you when you build the agent, your code before each model call, the model itself through a tool search, and the servers, which can add or remove tools while the agent runs.
