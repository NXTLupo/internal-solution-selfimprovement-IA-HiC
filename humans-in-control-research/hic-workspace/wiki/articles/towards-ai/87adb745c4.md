This week I opened the server log of the Ollama on my MacBook Pro and found it running Qwen3.5 on llama.cpp. That isn't wrong, exactly. But a month ago Ollama started running that model family on Apple's own MLX framework, and my Homebrew install was too old to know. I hadn't noticed. And when I upgraded, it still ran on llama.cpp.

That's the pattern with local models on a Mac. The settings that decide whether a model fits, and how fast it answers, are mostly defaults you never picked: which engine runs it, how much of your RAM the GPU plans to use, which quant you pulled, how long a context you get, and whether your prompt is re-read from scratch on every turn.

So I measured what each one costs in memory on my own machine (a 24GB M5 MacBook Pro, macOS 26.3.1) and took the speed side from Apple's, Ollama's and llama.cpp's published numbers. I didn't time anything myself. These are the five, in the order I'd check them.
