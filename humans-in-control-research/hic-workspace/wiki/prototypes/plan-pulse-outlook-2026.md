## Concept
=== APPROVED PRODUCT BRIEF (the user picked this from a 5-brief set; build EXACTLY this) ===

Frame: convention-honoring (probability 0.4)
Title: Plan Pulse Outlook 2026
Thesis: A consultant workspace that turns tokenized client data into deterministic, QC-locked 2026 insurance-outlook reports clients can trust.
Why this frame: It honors the package's stated v1 scope exactly: a SOC-2, no-PHI, Azure-hosted standalone reporting platform where consultants ingest, QC, generate, and deliver per-client benefit reports.

PRIMARY PERSONA:
  Name: Jayaprakash Menon
  Role: NFP Integration Lead & Senior Benefits Consultant
  Context: Works inside NFP's estate over the site-to-site VPN; responsible for producing defensible 2026 insurance-outlook reports for a portfolio of employer clients from tokenized Microsoft Fabric data, then delivering them through compliant channels.
  Emotional state: Cautiously accountable - proud of the analysis but anxious that any number he ships can be traced, defended, and reproduced if a client or auditor challenges it.
  Pain points:
    - Spends hours reconciling whether the data behind a report is fully ingested or still mid-update, fearing he'll present an inconsistent state
    - Has no clean way to prove which numbers are client-sourced versus consultant-imported versus AI-derived when a CISO or client questions provenance
    - Manual Excel-to-deck handoffs break formatting and force re-keying for every client variation
    - Sharing reports externally is a security minefield - no easy allow-list, no takedown, no confidence about who can see what
  JTBD: When I have a client's tokenized benefits data, I want to ingest it cleanly, lock a canonical model, and generate a deterministic 2026 outlook report I can defend line-by-line, so I can deliver insight without ever risking a compliance or accuracy failure.
SECONDARY ACTORS:
  - NFP CISO Office reviewer: Assesses the security posture, audit-log retention, SIEM integration, and per-client isolation before production authorization.
  - QC Editor / Reviewer (internal NXT or NFP): Reviews flagged anomalies and the canonical model, then commits the QC lock that freezes report state.
  - External client recipient: Receives reports via one-time-code allow-list links or a delivered PDF; never holds an account; render is scoped to viewer permissions for live HTML.
  - Shane (CTO, NXT Humans / Product Owner): Authorizes scope changes, signs off on ADR transitions from Proposed to Accepted, and gates any PHI exception.
  - NFP landing-zone / platform admin: Owns hub-spoke decisions, CIDR allocation, VPN device details, DNS and TLS certificate ownership.

DEMONSTRATED MOMENT: From a tokenized Fabric feed passing closed-schema validation, through human QC review and a canonical lock, to a delivered deterministic 2026 outlook report - HTML and PDF - that a client and an auditor can both trust.

USE CASES (12) - the prototype MUST demonstrate at least 5 of these as live flows:
  1. Ingest tokenized Fabric feed against closed schema
     Trigger: Jayaprakash initiates an ingest for a client whose tokenized dataset has landed in the BC Pulse spoke over private connectivity.
     Flow: He selects the client and source (Fabric feed or validated Excel upload) → the closed-schema validator runs, rejecting unknown columns, wrong types, out-of-range values, and invalid enums → a validation report enumerates every rejection with clear feedback → on a clean pass, the dbt medallion pipeline (staging → intermediate → marts → api) builds into the per-client read-only store.
     AI role: AI assists only by clustering and ranking validation failures into human-readable groupings; it never transforms data and never enters the output loop.
     Outcome: A fully validated, schema-conforming dataset is staged in the per-client encrypted store, with raw PII and PHI having never crossed the tokenized boundary.
  2. Run quality control and lock the canonical model
     Trigger: Pipeline build completes and the canonical model is ready for human review prior to any report generation.
     Flow: Jayaprakash opens the QC surface (editor/admin only) → reviews flagged anomalies, distribution outliers, and completeness gaps → annotates or accepts each → confirms the canonical model is correct → clicks QC-lock → the system snapshots and versions the locked state.
     AI role: The QC anomaly flagger surfaces statistical outliers, missing-token clusters, and prior-period deltas with severity ranking, but a human always commits the lock.
     Outcome: A versioned, locked canonical model after which all report output is a deterministic function of the locked state - reproducible by anyone, at any time.
  3. Generate the 2026 insurance-outlook section set
     Trigger: With a locked canonical model, Jayaprakash requests the Plan Pulse 2026 outlook suite for the client.
     Flow: He selects the report suite → deterministic generation reads the one canonical model → projection metrics, plan-cost trends, and renewal-outlook sections compute → AI-assisted narrative drafts attach to each section with provenance labels → output renders as structured HTML.
     AI role: Narrative draft generator composes prose summaries from locked deterministic metrics; outputs are clearly marked DERIVED and never alter the numbers.
     Outcome: A complete 2026 outlook section set, every figure traceable to a source field, every narrative flagged by provenance.
  4. Compose report pages with section-by-page control
     Trigger: Jayaprakash wants to tailor which outlook sections appear for a specific client audience.
     Flow: He opens the composer → drags sections into a page sequence → toggles section visibility per audience → previews live → the layout persists against the locked model version.
     AI role: AI suggests a section ordering optimized for the client's plan profile (e.g., lead with cost-containment for high-trend clients), as a recommendation only.
     Outcome: A client-tailored report composition bound to a specific locked model version, ready for export.
  5. Export self-contained HTML and PDF artifacts
     Trigger: Composition is finalized and Jayaprakash needs deliverable artifacts.
     Flow: He triggers export → KEDA ScaledJob spins a headless PDF worker from zero → the same content produces a self-contained interactive HTML and a static PDF → both are versioned and stored.
     AI role: None in the output loop - generation is fully deterministic; AI is explicitly absent after QC lock.
     Outcome: Two self-contained artifacts: live HTML scoped to viewer permissions, and a static PDF identical for all viewers.
  6. Deliver via SSO and one-time-code allow-list links
     Trigger: The report is ready for an external client recipient who has no platform account.
     Flow: Jayaprakash adds the recipient to an allow-list → generates a one-time-code link → the recipient authenticates via the code → views the live HTML scoped to their permissions, or downloads the static PDF.
     AI role: None - delivery is a controlled, deterministic access path.
     Outcome: Secure external delivery with no client accounts, full access logging, and viewer-scoped rendering.
  7. Review AI-assisted derived metrics with provenance labels
     Trigger: A client or CISO questions where a particular figure came from.
     Flow: Jayaprakash opens the provenance inspector → selects the figure → sees its data domain (CLIENT / CONSULTANT / DERIVED) → traces it to source fields and the ADR governing its computation → exports a provenance card.
     AI role: Citation and source-field linker maps each rendered element back to its originating tokenized fields and computation lineage.
     Outcome: An auditable, exportable provenance trail for any number in the report, defensible to an auditor.
  8. One-action takedown of an external report link
     Trigger: A delivery needs to be revoked - wrong recipient, superseded version, or client request.
     Flow: Jayaprakash opens delivery management → finds the active link → clicks takedown → the link is revoked instantly and an audit event is recorded.
     AI role: None.
     Outcome: Immediate revocation with append-only audit evidence; the recipient can no longer access the artifact.
  9. Trigger re-ingest after upstream Fabric correction
     Trigger: NFP corrects tokenized data upstream and a fresh feed arrives.
     Flow: Jayaprakash starts a new ingest → schema validation re-runs → a new canonical model version is built → prior locked version remains immutable and citable → he re-runs QC against the new state.
     AI role: Anomaly flagger highlights deltas between the prior locked version and the new candidate.
     Outcome: Versioned re-ingestion preserving the audit chain; no report ever silently changes its numbers.
  10. Import consultant Strategy Excel data
     Trigger: Jayaprakash has consultant-sourced strategy inputs (CONSULTANT domain) to fold in.
     Flow: He uses the distinct Strategy Excel import (ADR-0016) → it validates against its own contract → merges into the canonical model tagged as CONSULTANT provenance → flows into QC.
