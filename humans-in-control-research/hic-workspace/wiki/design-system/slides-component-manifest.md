# SLIDES Component Manifest

The deck-native archetype library, harvested from Figma page `324:2` (NXT symbols `609:2-609:15`,
NU mode instances `626:*`). A `#slides` / `#presentation` / `#strategy` deck is COMPOSED from these
archetypes the way `#proto` is composed from `proto-component-manifest.md`: the model SELECTS the
archetype that fits each slide's content (varying them across the deck) and supplies the PAYLOAD;
`slideComposer` renders it from the registry anatomy + brand tokens (no per-archetype code). Brand is
a MODE flip (NXT 221:0 chartreuse/Saira; NU 535:0 navy+red/Lato), never a layout change.

## How to emit a deck slide (MANDATORY contract)
Each slide is one fence whose template id is the archetype with a `slides:` prefix:
```
:::slide template=slides:<archetype> brand=nxt|nu
{ ...PAYLOAD exactly as specified for that archetype (key names + array lengths verbatim)... }
:::
```
The `slides:` prefix ROUTES the slide through the registry composer; without it the slide falls back
to a legacy template. Field names and array lengths below are a contract - the composer reads them by
exact key. Pixel anatomy + token bindings per archetype:
`plans/figma-audit/slides-archetypes/group-{a,b,c}-*.md`.

## Selection doctrine (this fixes "no variety / repeats one template")
- A deck OPENS with `slides:cover`; for 6+ slides add `slides:agenda` second, and
  `slides:section-divider` / `slides:thesis-interstitial` between major sections.
- VARY the archetype to the CONTENT SHAPE - never repeat one body archetype slide after slide. A
  varied deck uses 5+ distinct archetypes; never 3 identical body archetypes in a row.
- DIAGRAM-SHAPED CONTENT LANDS ON A DIAGRAM BRICK (2026-07-09): 2x2 positioning ->
  `slides:quadrant`; a process/sequence -> `slides:flow-arc`; dated milestones ->
  `slides:milestone-timeline`; relative magnitudes -> `slides:ranked-bars`; option-vs-option ->
  `slides:comparison-panels`; the hero-figure MEANS/MATTERS stat anatomy -> `slides:means-matters`.
  Never render these shapes as plain text columns.
- Titles are conclusions; numbers ride only inside cited quotes; >=50% external sources.

## Type system (fully tokenized — 2026-06-18)
Every text size on these archetypes is bound to a Figma `type/scale/*` variable (collection `NXT
Brand Tokens` 221:2, both modes) — NO hardcoded px anywhere, in Figma or in `slideComposer`. The
deck scale: `kicker` 22, `caption` 18, `deckHeading` 24, `lead` 25, `name` 30, `subhead` 36, `title`
46, `deckTitle` 58, `display` 60, `numeral` 80, `hero` 120, `sectionNumeral` 360, `quoteMark` 260.
- **Body copy is 14pt-readable (`type/scale/body` = 28 stage px).** Reading prose (numbered-themes
  body + quote, stat MEANS/MATTERS, problem-diptych body/subhead, org-model definition, role
  challenge/need/action/impact bodies, role-roadmap items, evidence-table intro, section supporting,
  scene body) renders at the readable body size, single-spaced.
- **Tabular / dense-list cells stay compact (`caption` 18 / `label` 15-17):** evidence-table
  prove/implication cells, org-model team/outcome lists, sources, kickers, micro-labels. These are
  the documented exemption to the readable-body floor — bumping them to 28 overflows the dense grid.
- BUDGET CONSEQUENCE: because body is now larger, body fields must be COMPRESSED to fit (compress the
  idea, never truncate). Per-column synthesis body <= ~150 chars; MEANS/MATTERS <= ~110 chars;
  takeaway statement <= ~140 chars (2 lines). Emit `density=dense` only when the archetype's slots
  genuinely hold more, never to pad.

## Chrome modes
- **full-bleed-dark** (cover, section-divider, thesis-interstitial, problem-diptych): rail-colored
  canvas, NO 128px rail bar, giant Saira display, dot-mark bottom-left.
- **content-rail** (all others): 128px `color/rail` left bar, 3x3 accent dot-mark bottom-left, cyan
  kicker `top:40`, Saira 58px action title `top:86`, masthead logo, footer source `top:1014`.

## Archetypes (template id · NODE NXT/NU · WHEN TO USE · PAYLOAD)

### slides:cover — 609:2 / 626:2 · full-bleed-dark
Deck opener (one per deck). PAYLOAD: `{ wordmark, title, subtitle }`.

### slides:scene — interactive presentation scene (text + AI illustration) · full-bleed-dark
A narrative #presentation scene: a text block (kicker + action title + one body line) on the left and
a tasteful on-brand, transparent, minimalist abstract flat-vector ILLUSTRATION (Illustrator skill) on
the right. Use for #presentation content scenes that benefit from a supporting visual (not every scene).
PAYLOAD: `{ kicker, title, body, imageConcept, canvas }` where `imageConcept` = a literal SHAPES-AS-CONTENT
description of the scene's idea (e.g. "a human figure beside flowing lines converging to one point";
"many nodes converging into one unified shape") and `canvas` = "dark" (full-bleed-dark). The runtime
generates the illustration from imageConcept (contrast-aware) and injects it; do NOT supply an image URL.

### slides:agenda — 609:3 / 626:15 · content-rail
Table of contents after the cover. Two grouped, pre-numbered columns.
PAYLOAD: `{ title, groups: [ { label, items: [ "01: ...", "02: ..." ] } ] }` (1-2 groups, ~4 items each).

### slides:section-divider — 609:4 / 626:36 · full-bleed-dark
Opens a major section. PAYLOAD: `{ number, title, supporting }` (number is zero-padded "01").

### slides:thesis-interstitial — 609:5 / 626:49 · full-bleed-dark
One contestable assertion between sections. PAYLOAD: `{ kicker, thesis }` (thesis = ONE sentence).

### slides:stat-row — 609:6 / 626:61 · content-rail
By-the-numbers proof: exactly 3 figures, each with a qualitative MEANS + MATTERS.
PAYLOAD: `{ kicker, title, stats: [ { figure, headline, means, matters } ] (exactly 3), sourceLine }`.

### slides:block-quote — 609:7 / 626:95 · content-rail
One hero verbatim quote + a right panel of 3 corroborating data points.
PAYLOAD: `{ topicKicker, quote, attributionName, attributionRole, corroborating: [ { figure, label, source } ] (exactly 3), sourceLine }`.
OPTIONAL IMAGE (scenes-where-they-fit, USER OVERRIDE 2026-06-28): `panelImage` (a data-URI/URL) renders ONE supporting scene in the empty left band below the quote (Figma slot 901:477, 900x200). The runtime fills it from the quote subject; do NOT author a URL yourself. Omit if there is no supporting visual.

### slides:infographic-exhibit — composer-native · content-rail  <- the DATA VISUAL slide
The deck's native infographic slide (2026-07-02): kicker + action title + a FULL-WIDTH data panel +
the takeaway band. The panel is COMPOSED FROM YOUR PAYLOAD'S OWN STRUCTURED FIELDS by the native
render lane (never a scene, never diffusion): 3-5 steps/actions -> a process flow; a beforeAfter
pair -> a comparison; 2-5 labeled stats -> a stat row; a 2+ source-type citation mix -> an
evidence-mix composition. Use when a finding is STRUCTURAL (a sequence, a contrast, a distribution)
and prose columns would bury it; at most 1-2 per deck.
PAYLOAD: `{ kicker, title, takeaway: { label, statement }, sourceLine }` PLUS exactly ONE of:
`steps: [ { title, description } ] (3-5 moves: title = the named move, description = ONE sentence of substance - what happens and why it matters; a bare title renders an empty card)` OR `beforeAfter: { before: { points: [...] },
after: { points: [...] } } (2-4 points each)` OR `stats: [ { label, value, quote?, source? } ] (2-5;
values are QUALITATIVE words unless the number rides inside the cited quote)` OR `citations:
[ "named source", ... ] (4+ real named sources across types)`. Do NOT author an image URL
(exhibitImage is runtime-filled); do NOT emit this archetype without one of the four field shapes -
that is a protocol violation (the slide would render an empty panel).

### slides:numbered-themes — 609:8 / 626:124 · content-rail ← profile N items/apps/themes
4 numbered columns, each name + synthesis body + a verbatim quote. THE archetype for "profile each
app/theme/play". PAYLOAD: `{ kicker, title, items: [ { number, name, body, quote, depiction? } ] (4), sourceLine }`.
When items profile PEOPLE/segments, each item may carry `depiction`: one literal sentence describing
the representative person the item photograph shows, every attribute derived from the corpus signal
about that segment (quoted individuals, regional/generational markers, workforce data); attributes the
corpus does not support stay unstated. The runtime treats stated attributes as binding on the image.

### slides:evidence-table — 609:9 / 626:158 · content-rail ← named-subject comparison
4-column comparison; first ~2 rows are featured; closes with a PEER PATTERN takeaway band.
PAYLOAD: `{ kicker, title, intro, columns: [ 4 column labels ], rows: [ { subject, prove, implication, evidenceGrade, featured } ] (~6; first 2 featured:true), takeaway: { label, statement }, sourceLine }`. TITLE <= 70 chars (1-2 lines max - the dense table has no room for a 3-line title); intro <= 1 sentence; prove/implication cells <= ~90 chars (2 lines).

### slides:problem-diptych — 609:10 / 626:213 · full-bleed-dark
Two contrasting halves as equals. PAYLOAD: `{ eyebrow, title, subhead, cards: [ { numeral, heading, body } ] (exactly 2) }`.

### slides:org-model — 609:11 / 626:236 · content-rail
A 3-part operating model as 3 peer columns (NOT a reporting-tier chart).
PAYLOAD: `{ eyebrow, title, columns: [ { name, definition, teams: { label: "TEAMS", items: [..] }, outcomes: { label: "OWNED OUTCOMES", lines: [a, b] } } ] (3) }`.
OPTIONAL ICON (scenes-where-they-fit, USER OVERRIDE 2026-06-28): each column may carry a CONTENT-TRUE operating-model glyph in the empty card-bottom band (Figma slots 901:5476/5477/5478, 72x72). The runtime resolves a tokenized glyph per column from that column's name/definition (carrier `columnIcons[]` index-aligned to `columns`, or `columns[i].icon`); do NOT author a URL. Content-true or nothing - never decoration.

### slides:role-needs — 609:12 / 626:286 · content-rail
One role's current challenges (left) + that role's persona-needs card (right). G1 of the role trio.
PAYLOAD: `{ eyebrow, title, role, challenges: [ { numeral, heading, body } ] (3), persona: { needsLabel: "PERSONA NEEDS", name, depiction?, needs: [ { kind, body } ] (3) } }` (kind = EXPERIENCE | FUNCTIONAL | PERSONAL).
`persona.depiction` (optional, any industry/persona type): one literal sentence describing the
representative person the environmental portrait shows (age band, gender, attire, working setting,
regional cues), every attribute derived from the corpus signal about this segment; attributes the
corpus does not support stay unstated. The runtime treats stated attributes as binding on the image.

### slides:role-recommendation — 609:13 / 626:324 · content-rail
One role's recommendation: thesis + 3 supporting actions + 3 projected-impact tiles. G2 of the trio.
PAYLOAD: `{ eyebrow, title, role, thesis, actions: [ { numeral, heading, body } ] (3), impact: [ { label, headline, body } ] (3) }` (label e.g. REVENUE | C-SAT | SERVICE NEEDS).

### slides:role-roadmap — 609:14 / 626:367 · content-rail
One role's phased roadmap across 4 phase columns. G3 of the trio.
PAYLOAD: `{ eyebrow, title, role, phases: [ { label, name, items: [ ".." ] } ] (4) }` (label e.g. "PHASE 01 · MONTHS 1-6").

### slides:aggregate-roadmap — 609:15 / 626:425 · content-rail
One roadmap across roles: role-rows x horizon-columns matrix. The cross-role closer.
PAYLOAD: `{ eyebrow, title, horizons: [ 4 column labels, last emphasized ], roles: [ { name, cells: [ one per horizon ] } ] }`.

### slides:quadrant — composer-native (Figma canon write-back pending, WS-2) · content-rail ← 2x2 positioning
A 2x2 strategy quadrant: two axis labels, four titled quadrant cells (quadrant order TL, TR, BL,
BR), and 3-8 plotted subject chips rendered inside their quadrant as accent-bordered chips. Use
when the finding POSITIONS named things against two dimensions (value vs effort, urgency vs
impact); never fake a quadrant with text columns.
PAYLOAD: `{ kicker, title, xAxis, yAxis, quadrants: [ { title, items: [ ".." ] (<=3) } ] (exactly 4,
order TL/TR/BL/BR), subjects: [ { label, quadrant } ] (3-8; quadrant = 1-4 -> TL/TR/BL/BR), sourceLine }`.
BUDGETS: title <= 70 chars; xAxis/yAxis <= 60 (name BOTH poles, e.g. "DELIVERY EFFORT (LOW TO
HIGH)"); quadrant title <= 24; each item <= 60; subject label <= 28. At most 3 subjects land per
quadrant (extras drop in payload order) - spread them. DENSITY: fixed 4 quadrants; `density=dense`
does not raise ceilings here.

### slides:flow-arc — composer-native (Figma canon write-back pending, WS-2) · content-rail ← process / sequence
3-6 numbered step cards in a horizontal band with native connector bars between them; steps
spread to fill the zone at any count. Optional `outcome` closes the slide with an accent OUTCOME
band. THE brick for process-shaped content (phases, pipelines, operating loops) - never render a
sequence as prose columns. Step numbers are AUTOMATIC from order; do not author them.
PAYLOAD: `{ kicker, title, steps: [ { title, description } ] (3-6), outcome?, sourceLine }`.
BUDGETS: title <= 70 chars; step title <= 30 (2 lines); description = ONE complete sentence of
substance, <= 170 chars (what happens and why it matters - a bare label renders a hollow card);
outcome <= 140 (2 lines on the band). DENSITY: 4 steps base; `density=dense` warrants 5-6.

### slides:milestone-timeline — composer-native (Figma canon write-back pending, WS-2) · content-rail ← dated milestones
A horizontal time axis with 3-6 milestone nodes: accent dot on the axis, mono date label, title +
one-line detail alternating above/below the axis (collision-free by construction). Use for dated
commitments, rollout gates, history arcs - anything where WHEN carries the argument.
PAYLOAD: `{ kicker, title, milestones: [ { date, title, detail } ] (3-6, chronological), sourceLine }`.
BUDGETS: title <= 70 chars; date <= 14 chars (e.g. "MAR 2026", "Q3 2026"); milestone title <= 28
(2 lines); detail = ONE line of substance, <= 60 chars. DENSITY: 4 milestones base;
`density=dense` warrants 5-6.

### slides:means-matters — composer-native (Figma canon write-back pending, WS-2) · content-rail ← hero-figure stat anatomy
The two-layer stat anatomy (Farm-reference pattern): 2-3 columns, each an accent hero figure +
plain caption + MEANS label (cyan mono) + readable interpretation + MATTERS as a DARK CARD (rail
background, accent text); ONE source line closes the slide. Distinct from `slides:stat-row`: the
figure defers to the action title (numeral tier, never hero) and the MATTERS layer is a card.
Use when 2-3 evidence-carried figures each need an interpretation AND a consequence.
PAYLOAD: `{ kicker, title, stats: [ { figure, caption, means, matters } ] (2-3), sourceLine }`.
BUDGETS: title <= 70 chars; figure <= 8 chars (rides a cited quote in sourceLine per the
quantitative-claim rule, e.g. `Source: "One in three briefs stalls before synthesis." (Practice
operations review)`); caption <= 40; means <= 110; matters <= 110. DENSITY: fixed 2-3 columns;
`density=dense` does not raise ceilings here.

### slides:ranked-bars — composer-native (Figma canon write-back pending, WS-2) · content-rail ← relative magnitude
Horizontal proportional bars: 3-6 rows, each label (left) + accent bar on an ecru track scaled by
a 0-100 RELATIVE value + note (right). The value is NEVER rendered as text - it sets the bar
length only; any figure the reader sees rides a cited quote in the note. Use when the finding is
a RANKING or distribution (where the hours go, which drivers dominate).
PAYLOAD: `{ kicker, title, bars: [ { label, value, note } ] (3-6, sorted descending by value;
value = integer 0-100 relative magnitude, top row = 100), sourceLine }`.
BUDGETS: title <= 70 chars; label <= 28 (2 lines); note <= 90 chars (2 lines; carries the cited
quote when a figure matters). DENSITY: 4 bars base; `density=dense` warrants 5-6.

### slides:comparison-panels — composer-native (Figma canon write-back pending, WS-2) · content-rail ← option-vs-option
2-3 side-by-side option panels, each a dark header band + one cell per criterion, aligned across
panels on shared hairline rows with the criterion labels in a left rail column. Distinct from
`slides:evidence-table` (row cards profiling named subjects on ONE axis): this brick compares
OPTIONS down a shared criteria list (build vs buy vs assemble, vendor A vs B).
PAYLOAD: `{ kicker, title, criteria: [ ".." ] (3-5 labels), panels: [ { name, cells: [ one per
criterion, same order ] } ] (2-3), sourceLine }`.
BUDGETS: title <= 70 chars; criterion label <= 24 (uppercase rendered); panel name <= 20; each
cell <= 110 chars (2-3 lines, a judgment not a paragraph). DENSITY: 4 criteria base;
`density=dense` warrants 5.

> The `slides:role-needs` / `slides:role-recommendation` / `slides:role-roadmap` trio is ONE narrative
> set per role: emit all three with the same `role` value and matching eyebrow suffix.
> `slides:aggregate-roadmap` folds every role's roadmap into a single matrix.
