# Data Source Connector Catalog

This is the master reference for every data source connector registered in the HiC Research platform. The platform provides approximately 150 structured connectors spanning academic literature, government data, news media, AI research, social communities, and more. Every connector routes through a single proxy layer, giving the research fabric a unified interface regardless of the underlying data source protocol.

---

## Architecture Overview

All data source connectors are defined in `services/dataSourceConnectors.ts` and registered in a flat array (`ALL_CONNECTORS`). They share a common interface: `DataSourceConnector`, which exposes an `id`, `name`, `category`, `description`, and a `query()` method. Every query call is proxied through the research-proxy service on port 5012.

### Proxy Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/sources` | GET | List all registered source connectors |
| `/api/search/{source_id}?q=...&limit=...` | GET | Search a single source by connector ID |
| `/api/multi-search?q=...&sources=id1,id2&limit=...` | GET | Parallel search across multiple sources |
| `/api/extract-content?url=...` | GET | Full-text extraction via Jina Reader (PDF or web) |
| `/health` | GET | Proxy health check |

The proxy (`http://localhost:5012`) handles CORS, rate limiting, retries, and connector-type-specific response formatting. All client-side calls go through the proxy; direct service URLs are only used server-side. The default per-query limit is 15, capped at 50. Requests time out after 35 seconds for individual sources and 60 seconds for multi-search.

### Connector Factory Pattern

Every connector is instantiated via `createProxyConnector(id, name, category, description)`. This factory returns an object conforming to `DataSourceConnector` that:

1. Constructs the proxy URL from the `source_id`.
2. Calls `fetch()` with a 35-second `AbortSignal` timeout.
3. Maps the response into `DataSourceItem[]` with the appropriate `sourceType` and `credibilityTier`.
4. Returns a `DataSourceResult` including item count, query string, and timing.
5. On failure, logs a warning and returns an empty result (graceful degradation).

### Category-to-SourceType Mapping

Each category maps to a `sourceType` enum value used for downstream filtering and display:

| Category | sourceType |
|----------|------------|
| Higher-Ed News, News & Media, AI News, AI Lab Blogs, AI Policy | `news` |
| Academic Literature, AI Research, AI Models & Datasets, AI Conferences | `academic` |
| Education Data | `education` |
| Economic Data | `economic` |
| Government Data, Open Data Portals | `government` |
| Tech & Social, Video, AI Communities, AI Code | `social` |
| Web Intelligence | `web` |

## Credibility Tier Mapping by Category

Every source is assigned a credibility tier that affects how its evidence is weighted in the research corpus. See [[sources-registry/credibility-tiers]] for the full tier system specification.

| Credibility Tier | Categories |
|------------------|------------|
| **Tier 1** -- Peer-Reviewed / Government | Academic Literature, Education Data, Economic Data, Government Data, Open Data Portals, AI Research, AI Conferences |
| **Tier 2** -- Established News / Think Tank | Higher-Ed News, AI News, AI Lab Blogs, AI Policy, AI Models & Datasets, Video, Web Intelligence |
| **Tier 3** -- Community / Social | Tech & Social, AI Communities, AI Code, CX Mesh (Reddit, TrustPilot, Play Store) |

## CX Mesh Social Sources

The CX Mesh layer connects HiC Research to the existing Intelligence Augmentation platform tools via the CX Integration Service (`services/cxIntegrationService.ts`). These sources are accessed through the Reddit Ripper service (port 5001) and routed through the research proxy at `http://localhost:5012/api/cx`.

| Source | Service | Port | Credibility Tier | Notes |
|--------|---------|------|-----------------|-------|
| Reddit | Reddit Ripper | 5001 | Tier 3 | Subreddit posts and comments; AI-powered subreddit discovery via Gemini |
| TrustPilot | Reddit Ripper | 5001 | Tier 3 | Company review scraping |
| Play Store | Reddit Ripper | 5001 | Tier 3 | App review collection |

CX Mesh sources are configured per-plan via `enabledCategories.cxMesh` in the research plan generator, specifying subreddit names, TrustPilot company slugs, or Play Store package names. Default collection count is 100 items per target.

### AI-Powered Subreddit Discovery

The research fabric includes an AI subreddit discovery function (`discoverSubreddits()` in `researchFabricOrchestrator.ts`) that uses Gemini 2.5 Flash to recommend 5-8 relevant subreddits for a given research goal. Recommendations include:

- Subreddit name and description
- Relevance reasoning
- Estimated engagement level (high / medium / low)
- Approximate member count

## Deep Research Modes

In addition to data source connectors, the platform provides three AI-powered deep research modes implemented in `services/deepResearchService.ts`. These operate independently from the connector registry and use frontier model web search capabilities.

| Mode | Provider | Duration | Cost Estimate | Description |
|------|----------|----------|---------------|-------------|
| **Quick** (grounding) | Gemini 2.5 Flash | 5-15 seconds | $0.01-$0.05 | Fact-checking, current data lookup. 1-3 searches via Google Search grounding. |
| **Focused** | Claude / OpenAI Web Search | 30-120 seconds | $0.10-$0.50 | Topic exploration with iterative refinement. 5-20 searches with context building. |
| **Deep** | Gemini Interactions API | 5-30 minutes | $2.00-$5.00 | Autonomous multi-step research. Comprehensive landscape analysis. |

The deep research mode selection is presented to the user during plan generation. Each mode returns a `ResearchResult` containing synthesized content, cited sources (URLs + titles + snippets), search queries used, cost estimate, and execution duration.

### AI Query Refinement

Before executing a research plan, the orchestrator runs an AI query refinement step (`refineSearchQueries()`) using Gemini 2.5 Flash. This converts the user's high-level research goal into source-specific, optimized search queries (4-8 keywords each). Rules applied:

- News sources get year references (2025, 2026) for recency
- Academic sources get field-specific terminology
- Economic sources get indicator-relevant terms
- Social sources get community language rather than formal terms

## Content Enrichment Pipeline

After initial collection, the orchestrator runs two post-processing stages:

### 1. AI Relevance Scoring

All collected items are scored 0-100 for relevance to the research goal using Gemini 2.5 Flash (`filterAndScoreItems()`). Scoring criteria:

| Score Range | Meaning |
|-------------|---------|
| 90-100 | Directly addresses the research goal with specific data or analysis |
| 70-89 | Closely related, provides useful context or evidence |
| 40-69 | Tangentially related, might provide background |
| 0-39 | Not relevant -- dropped from corpus |

Items scoring below 30 are filtered out. If all items would be filtered, the top 5 by score are retained.

### 2. Full-Text Enrichment

Top-scored items (relevance >= 60) with short content (< 300 characters, typically just abstracts from academic APIs) are enriched via Jina Reader. The enrichment process:

- Fetches up to 12 items in batches of 3 concurrent requests
- Tries PDF download first, then web extraction
- Caps extracted content at 5,000 characters per item
- Tags enriched items with extraction method (`pdf` or `web`)

---

## Corpus Assembly

The `mergeResultsToCorpus()` function assembles all collected, scored, and enriched items into a structured text corpus for downstream AI analysis. Each item is tagged with:

- A sequential chunk ID (`CHUNK_001`, `CHUNK_002`, etc.) for citation tracking
- Relevance score out of 100
- Freshness score (see [[sources-registry/credibility-tiers]])
- Credibility tier label
- Full-text extraction flag where applicable

The corpus header includes a citation rule instructing downstream AI models to reference chunks using `[CHUNK_XXX]` format, ensuring every factual claim traces back to its source.
