# HiC End-to-End Workflow — Ideal Operation, Current State, and Gap Ledger

**Audience:** the successor agent who will VALIDATE everything. For each pipeline stage this gives
(A) how it SHOULD work if everything were correct and aligned to UNIFIED_VISION.md, (B) how it
ACTUALLY works today with file pointers, (C) the GAP, and (D) a concrete VALIDATION procedure.
Do not trust any "DONE" claim in here without running the validation. Verify against live code +
a live run; memories and plan docs reflect point-in-time state and drift.

**Read first:** `.claude/UNIFIED_VISION.md` (8 principles + CONVERGE/DELETE/GATE/SCHEDULE meta-principle
+ Track B Method A lego-brick doctrine), `.claude/CLAUDE.md` (design system SSOT, citation protocol,
banned phrases), `humans-in-control-research/CLAUDE.md` (3-tier architecture, model-routing rule,
manifest-chunk-retrieval rule). The canonical pipeline is: SPA (React, :5011 prod / :3000 dev) ->
Research Proxy (FastAPI, :5012, ~18K lines) -> external sources + hic-workspace/wiki (persistent KB).

**Standing doctrine that governs EVERY stage (UNIFIED_VISION):**
- **Anti-RAG / manifest grounding:** deliverables assemble from wiki + MANIFEST chunk POINTERS, never
  bulk-RAG injection of rawSources. RAG injection is the documented root cause of hollow deliverables.
- **Track B Method A (lego-brick):** the model composes deliverables from REGISTERED Figma bricks +
  tokens at generation time. The SPA NEVER calls Figma at runtime; Figma is canon, mirrored into
  `figma-tokens.json` + the renderer twins + `artifactImageSlots.ts`. Never hardcode hex/font/size.
- **Determinism-first for cached runs:** same corpus + goal -> same identity (temp 0 + seed) so the
  exact-cache can hit.
- **Quality-first:** meet quality floors by improving UPSTREAM, never by relaxing the gate.

## STAGE 1 — Data collection (broad, diverse, objective-anchored)

**IDEAL:** A research objective drives a broad, diverse pull across (a) integrated DATA PACKS
(curated per-industry source bundles, e.g. the Healthcare/Life-Sci 200-source pack), (b) the 200+
registered connectors (REST/RSS/CKAN/Socrata/arXiv/OpenAlex/Crossref/Semantic Scholar/Reddit/YouTube),
(c) deep social (reddit-deep per-subreddit), and (d) client uploads. EVERY collected item is SCORED
and ANCHORED to the user's research objective (objective-supremacy: relevance ranked against the goal,
not generic popularity), with a SOURCE-TYPE QUOTA so no single type (e.g. Reddit) dominates. Uploads
get vision-extraction (multimodal OCR) so PDFs/images become text. Result: a balanced SourceDocument[]
where >=50% themes cite external intelligence and >=40% of citations are non-upload.

**ACTUAL:** `services/researchFabricOrchestrator.ts` (~2,100 lines) fans out via proxy `/api/search/*`
+ `/api/multi-search`, dedups, chunks, assembles SourceDocument[]. Proxy `SOURCES` registry (proxy/app.py)
= 200+ sources, 8 connector types. Data packs exist (Healthcare/Life-Sci pack shipped). Objective-ranked
retrieval + upload vision-extraction (`_gemini_multimodal_extract`, gemini-3.5-flash, temp 0) shipped.
Source-type quota was a P0 from the research-run-failure-analysis (Reddit-skew).

**GAP:** (1) Verify the source-type QUOTA is actually enforced at collection time, not just documented
(research-run-failure-analysis flagged Reddit-skew as unfixed P0). (2) The 30K-char upload cap truncates
large uploads + 7x dupe bug + no by-name retrieval tier (project_article_capture_manifest_retrieval_diagnosis).
(3) Objective-anchoring is a ranking heuristic; confirm it actually demotes off-objective items rather
than just ordering them.
**VALIDATE:** Run a real objective; inspect the resulting corpus.json source-type distribution (is any
type >60%?); upload a 100+ page PDF and confirm full text captured + retrievable by name; check >=40%
non-upload citations in a generated deliverable.

## STAGE 2 — Data chunking

**IDEAL:** Each source is split into semantically coherent chunks (sentence/passage granularity),
each chunk independently embeddable + citable, with stable char-span offsets back to the source body.
Deterministic (same input -> same chunks) so caching + citation resolution are stable.

**ACTUAL:** Deterministic sentence-split (NOT LLM-based) -> per-chunk sqlite-vec store at
`wiki/.vectors.db`. `_search_chunked_articles`, `wiki_chunks_backfill` (proxy/app.py ~13900). Chunker:
`wiki_chunker.chunk_for_manifest`. Embeddings: `gemini-embedding-001` (or text-embedding-3-small/large).

**GAP:** In-page `chunks:` frontmatter char_spans can go STALE when a page body is edited (offsets shift);
they're only regenerated by the chunker (`POST /api/wiki/chunks-backfill?force=1&path_contains=<path>`
targeted, or `/api/wiki/retrofit-chunks?force=1` whole-wiki). The manifest SIDECAR self-heals via
`/api/wiki/manifest/reconcile` but the in-page spans don't. A prior wiki chunk-frontmatter corruption
(upsert regex bug, 8,367 pages) was purged — watch for recurrence.
**VALIDATE:** Edit a wiki page body, confirm its char_spans are re-chunked before relying on citation
offsets; spot-check a chunk's char_span actually slices the quoted text from the body.

**VALIDATE:** Run the wiki lint; confirm broken-link + orphan counts are trending down, not up.

## STAGE 4 — Frontmatter + citation mapping to chunks

**IDEAL:** Every chunk carries frontmatter (source, title, kind, key_terms, char_span). Every
`[CHUNK_XXX]` reference in generated content resolves to `"SourceName: ArticleTitle"`; comma lists
resolve to `"Sources: A, B"`; raw filenames to `"(Source: file)"`. No raw `[CHUNK_XXX]` ever leaks to
the reader. Citations name real sources; generic refs ("research", "studies") are banned.

**ACTUAL:** `citationResolver.ts` + `slidePostProcessor.ts` (~1,700 lines, the runtime chokepoint
enforcing .claude/CLAUDE.md output rules incl. citation rewriting, banned-phrase correction,
meta-narration stripping). `validate_chunk_citations.py` rejects deliverables citing wrong chunks.

**GAP:** The post-processor catches leaks defensively, but clever phrasing can bypass prompt rules
(the post-processor cannot be bypassed; the prompt can). Confirm no `[CHUNK_XXX]` or generic-citation
leaks in a live deliverable.
**VALIDATE:** Generate a deliverable; grep the output for `[CHUNK`, "research shows", "studies",
"various sources"; confirm 0 hits and every citation names a real corpus source.

## STAGE 5 — Data/chunk/citation integration into the manifest

**IDEAL:** A persistent manifest indexes every chunk with provenance + key_terms + per-source relevance,
enabling chunk-POINTER retrieval (not bulk injection). `pickChunksForPrompt()` pre-ranks; the
chunk-retrieval-strategist subagent handles dense/ambiguous cases. Any wiki write bumps a corpus-version
token that invalidates dependent caches.

**ACTUAL:** Persistent `.manifest.json` + journal (`.manifest.journal.jsonl`); index time 60s->0.5s;
~12,800+ records. `manifest-chunk-retrieval` skill is the contract; `generateThemes` is the reference
implementation. `_corpus_version()` = manifest base mtime + journal size.

**GAP:** Any generator still bulk-injecting `rawSources`/embedding-RAG instead of manifest pointers is
LEGACY to migrate, not a pattern to copy. Audit each generator for the grounding path it actually uses.
**VALIDATE:** For each deliverable generator, confirm it grounds via manifest chunk pointers
(`groundedViaManifest` gate) and not bulk RAG; check the proxy log for MANIFEST-CHUNK grounding lines.

## STAGE 6 — Data caching / saving (prompt caching to the max)

**IDEAL:** Layered caching minimizes cost + latency + quota draw: (a) provider-native PREFIX cache
(Anthropic cache_control 1h; OpenAI auto; Gemini implicit + explicit cachedContent), (b) app-level
EXACT-MATCH cache (deterministic requests skip the provider entirely -> $0 + quota-free), (c) tool/stage
cache (deterministic retrieval), (d) content-hash caches (embeddings, vision extraction, brand images).
ALL generation flows through ONE proxy chokepoint so caching is universal.

**ACTUAL (validated this session):** Full stack live in proxy/app.py. Exact-match cache PROVEN
(6.4x, $0 on hit). Anthropic prefix (1h) + OpenAI prompt_cache_key + Gemini explicit cachedContent
(env-gated) + tool cache + vision/embed content-hash caches. **KEY FIX 2026-06-28:** browser Gemini
chat/deliverables now route through proxy `/api/ai/gemini` (was direct @google/genai SDK, which BYPASSED
all proxy caching). Reference: `plans/prompt-caching-expertise-and-maximization-2026-06-28.md` +
`project_caching_stack_completion_2026_06_23` memory.

**GAP:** (1) Real deliverable re-gens MISS-then-STORE because grounded prompts aren't byte-identical
run-to-run (per-run chunk selection/query-expansion/learned-constraint injection vary) — the HIT
mechanism is proven but determinism-first must hold for re-gens to actually hit. (2) Per-worker cache
counters under-report across 4 uvicorn workers (size is shared sqlite; counters aren't) — telemetry
cosmetic. (3) Semantic cache shipped DORMANT (needs an offline unsafe-served-rate eval before enabling).
**VALIDATE:** `GET /api/ai/cache-stats`; send an identical deterministic request twice and confirm the
2nd is a hit; confirm no generation path calls a provider directly (grep services for
