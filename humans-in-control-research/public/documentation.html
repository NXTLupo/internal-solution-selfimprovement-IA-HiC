Humans in Control (HiC) is a research workbench that turns a research goal and a heterogeneous corpus (academic + news + government + social + client uploads) into consulting-grade deliverables with full citation traceability and cross-deliverable identity stability. A human operator drives every synthesis step. The system handles collection across 200+ data sources, multi-model resilient embedding + clustering, evidence-density-gated theme synthesis, and quality-gated artifact emission — surfaced through the Analyst Desk dashboard, the Analyst Chat workbench, the Design Desk + Designer window, the HTML artifact composer, and a wiki-as-RAG-store that lets the AI pull full article bodies on demand.

v4.2 focus (2026-05-24) — Smart Topic Modeling + Pipeline Hardening + Standing Rules. Today’s release lands the biggest single architectural reset of HiC’s theme synthesis layer plus a comprehensive pipeline-defense layer (14 new Stop hooks, 7 subagents, 6 new skills, 6 standing rules in agent memory).

(1) Smart topic modeling (topic_modeling.py run_pipeline_v2). After forensic comparison with internal-solutions-socialresearch/backend/util/BertTopic.py, the HiC theme pipeline diverges from the sister service in 4 HiC-specific ways: source-stratified clustering with cross-type centroid merge (clusters within each source-type bucket, then merges across types where centroid cosine ≥ 0.75 — surfaces themes convergent across academic + news + government + client as the strongest signal), coherence pre-filter on top-terms (drops noise clusters before LLM naming), evidence-density gate at cluster level (clusters need ≥2 distinct named sources or they’re dropped), and theme-count targeting by deliverable type (themes-only=25, strategy=7, persona_inputs=5, deck=12).

(2) Multi-model resilience layer. Replaces single-provider reactive fallback (try OpenAI; on 429 try Gemini) with four-layer resilience: content-hash embedding cache (provider-keyed; repeat-corpus runs pay zero embedding cost), provider health tracker (skip a provider for 10min after a 429), per-corpus provider commitment (no mid-corpus switching across embedding spaces), and signature-keyed cache for LLM identity-class calls (same cluster signature → same cached name regardless of provider stochasticity). LLM naming now runs at temperature=0 instead of unspecified-default-1.0.

(3) 14 new Stop hooks + 7 subagents + 14 new skills + 6 standing-rule memory entries. Pipeline now enforces evidence density, citation resolution, theme yield, evidence tier distribution, framework page existence, topic-model completion, corpus relevance distribution, AI output syntax repair, no silent fallback, deliverable coherence, quantification four-tuple, slide variety, theme reproducibility, and pre-export DOM audit — all at runtime. Standing rules now ban silent quality relaxation, mandate determinism for cached runs, require sister-service forensic reads before architecture decisions, require multi-model resilience as default pattern, and require finish-then-test execution.

1. What Humans in Control does

HiC is designed for a specific operator: a strategist or consultant who needs to go from a research brief to a defensible, evidence-cited deliverable in hours instead of weeks. It treats collection as a data fabric problem (not a search problem), treats synthesis as a multi-model agentic problem with deterministic identity layers and stochastic exploration layers (not a single-prompt problem), and treats the final artifact as a knowledge graph the user can navigate (not a static document).

Core claim. Every output element — themes, personas, barriers, recommendations — is traceable back to a named source, a tier, and a verbatim quote. Same cached corpus + same goal → same theme names + same cluster memberships (determinism enforced by BERTopic random_state=42, LLM naming at temperature=0, signature cache, and the validate_theme_reproducibility.py Stop hook).

2. Operator quickstart

  1. Enter a research goal. Be specific about the institution, outcome, and audience. The Brief Parser extracts named entities and seeds query refinement.
  2. Upload source documents. PDFs, plain text, CSV, JSON, transcripts. Client uploads shape personas + organizational framing but never dominate the citation base (60% external floor enforced).
  3. Select data sources. Toggle categories (Higher-Ed News, Academic Literature, Reddit Communities, Philanthropy, etc.). Defaults picked by Analytical Lens.
  4. Click Collect Data. The data fabric fans out, refines per-source queries with a 0.35 fidelity hallucination guard, scores body-aware relevance across 200+ connectors, and runs tri-model parallel analysis (Gemini + Claude + OpenAI) on top-ranked items.
  5. Land in the Analyst Desk. Themes auto-populate as a treemap. The v4.2 pipeline produces 15-25 themes natively from the corpus via BERTopic with auto-scaled hyperparameters — no relaxation tiers, no synthetic count floors.
  6. Inspect with breadcrumbs. Click any theme tile to see its cited evidence, linked sources, personas, and recommendations. Convergent-evidence themes (clusters that merged across ≥2 source types) are flagged.
  7. Refine via Chat to Data. Ask follow-ups. Every answer is grounded in corpus text with inline citations.
  8. Export. PPTX deck, PDF, PNG. The export-paint-sync skill defeats html2canvas race conditions; the export-render-verifier subagent QAs the rendered file.

3. Hashtag command system v4.2

The Analyst Chat (and Designer Chat) accept inline hashtag and slash commands that route requests through deliverable-specific generation pipelines rather than the conversational chat path. Type the directive(s), describe what you want, hit send.

Hashtag UX. Every directive is registered in services/hashtagRegistry.ts. Autocomplete: type # in chat — a styled dropdown appears with every directive, categorized, VS/CTX badges, navigable via Tab/Enter/Esc. #help: generates a live HTML reference guide artifact in a new window, sharable URL. Suggested chips: prepend the correct directive so one click ships an artifact, not a one-shot answer.

There are five distinct directive families:

  1. Experience builders — #proto (5-stage prototype pipeline with VS-reasoning), #presentation (multi-slide deck), #prototypes / #presentations (library browse). Produce interactive artifacts in new windows.
  2. Consulting deliverables (HTML artifact family) — #recommendations (VS-Multi: Defensible Consensus + Non-Obvious Bets), #brief (one-pager), #explainer (deep-dive), #report (long-form), #playground (interactive tuning surface), #approaches (3+3 decision picker), #artifacts (library). All compose verbalized-sampling + html-deliverable-composer skills. Most accept --variants k (2–6).
  3. Design Desk content hashtags — #org, #journey, #blueprint, #arch, #roadmap, #prd, #strategy, #gap, #audit, #compete, #persona, #case-study. Route to the Design Desk artifact pipeline.
  4. Brand & modifier — #NU, #NXT (brand modifiers), #slides (multi-slide composition modifier).
  5. Utility & system — #help, #refine <slug>: <tweak>, #explore, #patterns, #cross-engagement, #quantify, #pre-mortem, #stakeholder-lens, #analog, #dissent, #second-order, #fallback, #brain-status, #quota, #cost, #deterministic, #reproducible, #repair-syntax, #json-recovery, #orphans, #wiki-curate, #audit-recommendation, #failure-modes, slash: /image / /portrait.

Fabric pipeline

  1. Query refinement — per-connector query variants generated from goal + entities. Hallucination guard: if a refined query has 5-token fidelity < 0.35 vs the goal, replace with goal verbatim. Last run flagged 14/106 (13%) — guard worked.
  2. Body-aware relevance scoring — score each item on full body text (not headline-only). Distribution: HIGH / MODERATE / LOW.
  3. Tri-model parallel analysis — Gemini + Claude + OpenAI score top items concurrently. Validator validate_corpus_relevance_distribution.py fails if >85% of items are LOW (calibrated against the 2026-05-24 Northeastern run).
  4. Content enrichment — Jina Reader fetches full bodies for items lacking them; residual archival writes pre-existing 500-char+ bodies that bypassed enrichment.
  5. Wiki archival — every retrieved article persists to hic-workspace/wiki/articles/ with embeddings for semantic retrieval.
  6. Chunk-to-source map — [CHUNK_NNN] identifiers bind to canonical source names; citationResolver.ts resolves them at output time.

7. Institution-aware collection

HiC tracks 30 named institutions (Northeastern, MIT, Harvard, WPI, Drexel, Georgia Tech, BU, RIT, Waterloo, MSOE, CalState, etc.) via institutionManifest.ts. When a goal mentions an institution, the fabric:

  • Boosts query weights for that institution’s publications and press
  • Routes through institution-specific feeds (Higher Ed Dive university search, university PR)
  • Loads relevant uploaded documents from hic-workspace/sources/ if archived
  • Sources peer-institution baselines from hic-workspace/wiki/benchmarks/ for comparative analysis

8. The Analyst Desk

The Analyst Desk is HiC’s dashboard surface — a treemap of themes with breadcrumb drill-down into evidence, sources, personas, and recommendations. Inference happens progressively; each section’s status strip shows which stage is actively running.

Surfaces

  • Theme treemap — sized by evidence density (distinct named sources × citation count). v4.2: themes carry evidence_tier, convergent_evidence, source_types metadata. Convergent themes flagged visually.
  • Persona roster — Cooper goal-directed personas with JTBD statements, verbatim quotes, key metrics.
  • Journey map — Bitner 5-component model with fail points and emotion intensity.
  • Recommendation panel — VS-Multi: 5 Defensible Consensus + 5 Non-Obvious Bets. Each tile expandable to 12-field consulting brief.
  • Knowledge Library — cross-engagement Themes tab pulls from sessions/_topic-cache/*.json via new /api/topic-cache/* endpoints (v4.1+).
  • Cost meter — live $RUN total overlay during long-running generation (v4.1+).

9. Inference affordances

  • Reverse-pivot treemap — click a source chip to see only themes that source drives.
  • Read Archived — ⌘ READ ARCHIVED button on every evidence node opens the full article in a viewer.
  • Live Processing Indicator — pulsing dot + MM:SS elapsed counter on every long-running chat placeholder (v3.x).
  • Brain Status notice — inline indicator below deliverables that surfaces degradation_events[] (model substitutions, paint-sync warnings, retry storms). Powered by fallback-event-surfacing skill.
  • Reasoning Stream — live token stream during generation with stage markers.

10. Chat workbench & corpus Q&A

Post-collection, the Analyst Chat is the multi-turn Q&A surface over the corpus + all generated deliverables. Powered by Gemini 3.1 Pro primary (1M context, OpenAI-compatible tool-use). Native tools:

  • fetch_wiki_articles — semantic embedding-ranked retrieval from wiki/articles/
  • fetch_wiki_resource — read a specific wiki page by path
  • search_corpus_chunks — keyword + semantic search across collected items

Hashtag directives route requests through deliverable-specific pipelines instead of the conversational path. The verbalized-sampling skill is applied at every creative touchpoint (theme synthesis, recommendations, prototype concept decomposition, persona rostering, slide narrative authoring) to escape mode-collapse.

Mid-chat upload

Drop a PDF / DOCX / TXT into the chat dropzone mid-conversation. The proxy /api/parse-upload extracts text and archives it to wiki/uploads/. The chat session sees the new content as a context part on the next turn.

11. Design Desk & Designer window

The Design Desk is HiC’s artifact authoring surface. Trigger any artifact from the Analyst Chat with a hashtag command (#org #NU, #journey #slide). A dedicated Designer browser window opens (never replaces Analyst Desk) and renders consulting-grade 1920×1080 HTML artifacts using brand-locked exemplars.

Cross-window sync

  • BroadcastChannel — primary transport between Analyst Chat and Designer window
  • IndexedDB — durable storage; survives window close + reopen
  • designDeskStore.v1.sync — channel name; logged on boot

Multi-artifact loop

Each content hashtag in a single prompt generates one artifact, added to the design store via addArtifact() and broadcast in real time. Order doesn’t matter; plurals dedupe; brand defaults to #nxt if unspecified.

12. Freeform HTML artifacts

Five legacy kinds route through the freeform HTML pipeline: #org, #journey, #arch, #roadmap, #blueprint. Persona keeps the legacy SlideCanvas + PPTX export path. Twelve case-study slides (v4.2) use the new case-study framework page.

The composer inherits brand-locked CSS from public/nu-design-gallery/ (NU) or NXT brand tokens. Plain text only in generated content (no markdown bold/italic/headers); the renderer owns formatting. Per-stage emission limits enforced by validate_budgets.py Stop hook.

15. Multi-model resilience layer v4.2

Replaces single-provider reactive fallback with a four-layer resilience pattern. Lives in proxy/topic_modeling.py; should extend to services/aiRouter.ts as engineering follow-on.

The four layers

  1. Content-hash embedding cache — same (provider, content) → cached vector on disk at sessions/_embedding-cache/. Provider is part of the key because OpenAI 1536-d and Gemini 3072-d vectors aren’t interchangeable. Repeat-corpus runs pay zero embedding cost.
  2. Provider health tracker — _provider_health dict tracks last_429_at + consecutive_429s + total_429s. After a 429, skip the provider for THROTTLE_COOLDOWN_S = 600 (10 min) in auto-routing. Reset on success.
  3. Per-corpus provider commitment — once you pick a provider for a corpus, embed everything with that provider. Mid-corpus switching mixes vector spaces and breaks downstream clustering.
  4. Signature-keyed name cache — for LLM identity-class calls (theme names, persona names), hash the INPUTS to the call (top_terms + sample_titles + research_goal) and cache the OUTPUT. Same inputs → same cached output regardless of which provider would name it fresh. Resolves the determinism gap when temperature=0 alone isn’t strictly deterministic (e.g., Anthropic seed isn’t honored on all endpoints).

23. Export

Three export targets: PPTX (pptxgenjs), PDF (jspdf), PNG (html-to-image / html2canvas). The export flow:

  1. User clicks Export Deck PPTX/PDF or per-slide PNG
  2. export-paint-sync skill prep: fonts loaded (document.fonts.ready), images decoded, double-RAF for React stability, body[data-export-mode] CSS class set to hide editor UI
  3. Per-slide capture via html2canvas with onclone @font-face re-injection (defeats html2canvas iframe isolation font loss)
  4. PPTX: pptxgenjs emits slides; per-slide template implementations in components/slideTemplates/pptx.ts
  5. PDF: jspdf assembles pages; pixel-to-pt downscaling
  6. PNG: per-slide image download
  7. export-render-verifier subagent (if Playwright MCP installed): drives the actual export, screenshots every slide, validates against 9 defect classes

Defect classes the export-render-verifier catches

  • Blank slide (pixel entropy / OCR text count below threshold)
  • Leaked editor UI (OCR for Delete/Edit/Save/Cancel keywords)
  • Preview-export parity drift (perceptual hash distance)
  • Font fallback (glyph shape similarity to expected brand font)
  • Slide count mismatch (deliverable.slides.length vs export pages)
  • Section label mid-word break (CHALLENG / E, APPROAC / H pattern)
  • Brand wordmark missing in sidebar
  • Attribution clipping (text bleeds off panel edge)
