4. Source Curation System

Architecture

The curation system implements the "Humans in Control" principle: users control which evidence reaches every deliverable.

State Management

  • excludedSources: Set<string> — Keys: "sourceId::articleIndex" or "kg::nodeId"
  • prioritySources: Set<string> — Same key format, marks articles for mandatory citation
  • Default state: ALL articles INCLUDED (only excluded items tracked)

Filtering Pipeline

  1. At Ingestion: Corpus text filtered by excludedSources before ingestContext() — excluded articles never reach the Gemini chat session
  2. At Report: liveSourceResults filtered into curatedSources before generateStrategicReport()
  3. Evidence Catalog: ALL included articles injected (no per-source caps). Priority articles sort first.
  4. KG Exclusion: kg::nodeId keys matched via full title + 40-char prefix (dual strategy)

Priority Citation Enforcement

  • Priority articles marked with *** PRIORITY CITATION *** in evidence catalog
  • Report prompt mandates: "You MUST cite EVERY priority-flagged article by name"
  • No post-generation validation that priority articles were actually cited (see Known Issues)

Deterministic Slide Enrichment

After AI generates content blocks and layout resolution runs, a deterministic enrichment step injects report data directly into slides:

  • Empty metrics[] → filled from report section keyMetrics
  • Empty quote → filled from report section keyQuote
  • Empty sources[] → filled from report section citations
  • Short content labels (<40 chars) → replaced with report section evidence sentences

Body slides use ONE adaptive renderer (not rigid archetype templates). The renderer shows whatever content exists:

  • Right data panel: only appears IF metrics, bento cells, or right-side quote exist

7. Wiki Self-Improvement Engine

Cross-Session Learning

  • Edit Capture: Every user edit logged via logEdit(stage, field, original, edited)
  • Pattern Detection: After 5+ similar edits, constraint auto-approved (e.g., "persona quotes < 200 chars")
  • Constraint Injection: getActiveConstraints() injected into report + deck generation prompts
  • Wiki Export: exportConstraintsToWiki() persists to wiki/synthesis/learned-constraints.md
  • Engagement Memory: saveEngagementMemory() caches results per goal slug for cross-session recall

11. UAT Scenarios

UAT-001: End-to-End Research Quality

Scenario: A user conducts research on "Higher Education CX Strategy" with 5 uploaded documents and 10+ data sources enabled.
Acceptance Criteria:
  • Report cites 20+ distinct named sources (not "research" or "intelligence_sources")
  • Report includes at least 3 case studies with named institutions
  • Report includes verbatim social evidence (Reddit/forum quotes)
  • Every deliverable tab shows EvidenceBlock with citations and evidence basis
  • Deck slides have source citation pills visible
  • Excluded articles do NOT appear in any output
  • Priority articles ARE cited in the report

UAT-002: Source Curation Control

Scenario: User excludes all Tier 3 (community) sources, keeps only T1 + T2.
Acceptance Criteria:
  • No Reddit, forum, or community source cited in report or deck
  • Themes grounded exclusively in academic + news sources
  • Persona evidence arrays cite only T1/T2 sources

UAT-003: Deck Visual Quality

Scenario: User generates a strategy deck and exports as PDF.
Acceptance Criteria:
  • No blank/empty slide panels
  • Every body slide has at least 2 evidence points or metrics
  • Slide titles are conclusion sentences (not topic labels)
  • No meta-narration ("Good morning", "We will present")
  • PDF size < 40MB
  • PPTX renders all archetypes correctly

UAT-004: Self-Improvement Learning

Scenario: User runs 2 analyses. In session 1, they consistently shorten persona quotes. In session 2, the system should auto-apply the constraint.
Acceptance Criteria:
  • Session 1: edits logged, pattern detected after 5+ edits
  • Session 1: constraint auto-approved ("persona quotes < X chars")
  • Session 2: constraint loaded from wiki on startup
  • Session 2: persona quotes generated shorter without user intervention

12. Known Issues & Unfinished Work

This section documents all known defects, partially implemented features, and unfinished instructions from the product owner.

Critical Issues

CRITICAL KI-001: Strategy Deck Output Quality

The deck output (PDF/PPTX) still does not consistently reflect the depth of collected research data. While the content-block system and report-first architecture are implemented, the AI sometimes generates thin content blocks that result in slides with minimal evidence. The deterministic enrichment step helps but cannot fully compensate for thin AI output.

Root Cause: Gemini 2.5 Flash may produce minimal content blocks when given a complex 12-type schema. The per-slide report section matching can miss sections due to sourceDeliverable mismatches.

Workaround: Deterministic enrichment injects report metrics/quotes/citations into thin slides. Users should review at Narrative checkpoint and provide feedback to regenerate.

Status: Partially mitigated. Needs further prompt engineering on the narrative generation prompt.

CRITICAL KI-002: PPTX Export Still Uses Old Archetype Renderers

The HTML renderer was replaced with an adaptive renderer, but the PPTX export in exportService.ts still uses the old 7 rigid archetype renderers. This means PPTX output may have broken templates (empty data panels, mismatched layouts) even when the HTML preview looks correct.

Status: PPTX export not updated to match adaptive renderer. Needs complete rewrite of PPTX slide generation.

CRITICAL KI-003: No Validation That Priority Articles Were Actually Cited

The prompt says "MUST cite every priority article" but there is no post-generation validation. The AI may ignore priority flags. No error or warning is shown to the user if priority articles are missing from the report.

Status: Unimplemented. Needs post-generation scan of report text for priority article titles.

High Issues

HIGH KI-004: Deliverable Evidence Still Depends on AI Compliance

While Gemini schemas now REQUIRE citations[] and evidenceBasis as fields, the AI may return empty arrays or generic strings. There is no post-generation validation that these fields are actually populated with real source names.

Status: Schema enforcement in place but no content validation layer.

HIGH KI-005: Persona Enrichment Uses Standalone Call Without Full Corpus

Persona enrichment deliberately uses a standalone Gemini call (not the chat session) to avoid context contamination. This means the persona AI only sees the roster + theme citations (up to 20 evidence quotes), NOT the full 500KB+ research corpus. Personas may have thinner evidence than themes.

Status: By design (prevents context pollution), but limits evidence depth. Theme evidence injection added as mitigation.

HIGH KI-006: 500KB Corpus Cap at Ingestion

The research corpus text has a hard 500KB cap in mergeResultsToCorpus(). With 500-1500 collected items, lower-relevance items get truncated from the corpus. These truncated items still appear in the Knowledge Graph (which reads raw data) but don't reach theme/persona generation.

Status: Known design trade-off. Report generation bypasses this via direct rawSources injection.

HIGH KI-007: Report Checkpoint Textarea Sizing

Report section textareas use rows={Math.ceil(content.length / 90)} which is an approximation. Very long sections may still require scrolling. No auto-resize on user input (only initial sizing).

Status: Partially fixed. Could benefit from ResizeObserver or onInput auto-height.

Medium Issues

MEDIUM KI-008: No Dedicated Themes Output Tab

Themes are the foundational deliverable but have no dedicated tab in ResultsView. They're visible in the checkpoint and referenced in the knowledge graph, but users cannot view/export themes as a standalone output.

Status: Unimplemented. Themes tab in ResultsView needed.

MEDIUM KI-009: Competitive Analysis Missing Benchmark Dimensions + Maturity Matrix in Rendering

The competitive analysis generates benchmarkDimensions[], maturityMatrix[], and gapSummary[] but only peers are rendered in the output tab. The full competitive positioning data is generated but hidden.

Status: Partially rendered. Needs maturity matrix table + gap summary visualization.

MEDIUM KI-010: Priority Sources Not Persisted to localStorage

excludedSources is persisted to localStorage but prioritySources is not. Priority flags are lost on page refresh.

Status: Unimplemented.

MEDIUM KI-011: D3 Knowledge Graph Not Keyboard Accessible

The force-directed graph uses D3 SVG elements with no ARIA attributes or keyboard navigation. Screen readers cannot interpret the graph structure.

Status: Known accessibility gap. Detail panel is accessible; graph is not.

MEDIUM KI-012: Tech Architecture Sections Not Rendered in Output Tab

Tech Architecture generates 10 sections (current state, future state, data arch, security, etc.) but the output tab only shows the node diagram and basic node details. The rich section content is hidden.

Status: Unimplemented in rendering.
