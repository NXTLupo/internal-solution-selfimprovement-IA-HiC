Architecture overview

The target state extends the existing Northeastern data spine with two new integration boundaries: a donor-affinity tag on placement events, and a FERPA-bridged identity layer between Salesforce EDU and Raiser's Edge. Triage logic stays inside the co-op domain; advancement reads aggregated signals only. Two satellite CRMs and the legacy events platform retire to fund the work.

Architecture concerns

ten sections · each grounded in evidence, not boilerplate

§01Executive summary

Two new integration boundaries land in FY27; everything else extends existing platforms. Three satellite systems retire to fund the work.

§02Current state

15 disconnected systems; placement-to-donor lag of 11 days; no shared identity layer between SF EDU and Raiser's Edge. 4

§03Future state

FERPA-bridged identity layer (N-10) writes aggregated signals only across the bridge. Co-op data stays in co-op domain.

§04Data architecture

Two Snowflake warehouses persist; identity bridge sits between them with append-only audit log. No data movement; signal contributions only.

§05Integration architecture

Webhook-first for activity events (low-latency); ETL only for batch warehouse jobs. Single canonical ID across the bridge.

§06Security

Okta SSO; service-to-service mTLS; aggregated-signal contract enforced at the bridge layer; 5-year audit retention.

§07Scalability

Activity event volume ≈ 8K events/day at peak cycle; webhook path designed for 10× headroom. Triage queue renders 180 entries <1 s.

§08Tech stack rationale

React + Snowflake + Salesforce — existing investments. No net-new vendor relationships. Two satellite CRMs retire (R-07).

§09Gap analysis

Largest gap: cross-record identity. Largest risk: GC sign-off on the aggregated-signal contract. See gap-analysis.html.

§10Risks

FERPA exposure on the bridge (mitigated by aggregation); webhook latency (mitigated by hourly backfill); coord rejection of queue (mitigated by opt-in pilot).
