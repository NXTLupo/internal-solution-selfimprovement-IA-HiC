# AI UX/UI Analyst Agent — v5.2 + v5.3 Upgrade Recipe (Grounded Research + Synthesis Quality)

This recipe walks you through every click, field, toggle, and configuration needed to add the v5.2 Grounded Research capability to your existing AI UX/UI Analyst Agent flow in Power Automate. The upgrade adds a pre-research step that uses Claude's web search tool to verify all competitive benchmarks and statistics before they reach the per-screen analysis loop. This eliminates hallucinated statistics, fabricated competitor feature descriptions, and misattributed data points from your reports. Written for someone who has already built the v5.0/v5.1 flow and needs to add the new actions in the right place.

---

Prerequisites — What you need before starting

Before you begin, confirm you have the following:

1. Your existing AI UX/UI Analyst flow open in Power Automate at https://make.powerautomate.com. The flow should already have these actions in order: Trigger → Initialize Variable block (varRollingMemory, varFileCount, varScreenAnalyses, varAssistantHTML, varHTMLStopReason, varHTMLLoopCount, varImageMap) → Get Screenshot Files → Get_Anthropic_Key → Respond to Copilot → Loop_System_Prompt → Escape_Loop_System_Prompt → Apply_to_each (per-screenshot loop) → Synthesis → HTML Do Until → Image Injection → Output.

2. Your Anthropic API key working, stored in the `Get_Anthropic_Key` Compose action (or however your flow currently retrieves it). The same key works for the Research calls.

3. Confirm your Anthropic API key has access to the `web_search_20250305` tool. This is available on all Claude API plans. If you are unsure, test with Step 3.6 before proceeding.

4. A text editor (Notepad, VS Code, or similar) open alongside Power Automate for copying long prompt text and expressions. Several expressions in this recipe approach the 8,192 character Power Automate expression limit.

2. Why two research calls instead of one: Each HTTP action in Power Automate has a **hard 120-second synchronous timeout**. A single research call with 15+ web searches can take 90-180 seconds, risking timeout. Splitting into two focused calls — one for the brand + competitors (max 8 searches), one for industry data + design patterns (max 7 searches) — keeps each well under 120 seconds while providing the same coverage.

> **CRITICAL**: The Initialize varResearchContext goes in the Initialize Variable block. The Research actions (Compose, Escape, HTTP, Extract, Merge, Set) go AFTER Respond to Copilot but BEFORE Loop_System_Prompt. Both research calls must complete before any per-screen analysis begins.

# PHASE 3: Build the Research API Calls

This phase creates the research actions: one shared system prompt, two focused user prompts with their escape chains, two HTTP calls, two extract actions, one merge, and one Set Variable. Total: 12 new actions.

## Step 3.1: Create the Research_System_Prompt Compose Action

WHERE AM I?: Power Automate > Flow Editor > Directly below Respond to Copilot, ABOVE Loop_System_Prompt

1. Find the Respond to Copilot action. Click the + button directly below it.

2. Search for "Compose" → select Compose (under "Data Operations").

3. Click the three dots (...) → Rename → type: Research_System_Prompt

4. In the Inputs field, paste the following text exactly:

```
You are a competitive intelligence researcher preparing verified data for a UX audit.

Your job: Research the brand, its competitors, and the industry. Use your web search tool to verify every factual claim. Return ONLY what you can confirm with real sources.

RESEARCH PROCESS:
1. Search for the brand being analyzed — what AI/chat features do they actually have? What's their current digital experience?
2. For each competitor in this brand's space, verify: Does the feature described actually exist? Does it work the way described?
3. For each statistic, verify: Is this a real published number? From the attributed source? If the real number is different, use the real one.
4. Search for additional relevant competitors or data points specific to this brand's industry.

WHAT TO VERIFY:
- Competitor feature claims (e.g., does a routine builder show step-by-step sequencing? What does it actually show?)
- Specific statistics with attributions (e.g., is "60% higher completion" published by the attributed source?)
- Product/feature descriptions (e.g., what does a virtual artist tool actually do?)
- Industry reports and their findings (do the cited numbers match the actual report?)

OUTPUT FORMAT — return ONLY valid JSON:
{
  "brand_research": {
    "brand_name": "string",
    "current_ai_features": ["description of each verified AI/chat feature the brand actually has"],
    "current_experience_notes": "what the brand's digital experience actually looks like today"
  },
  "verified_benchmarks": [
    {
      "competitor": "string",
      "feature": "string — what the feature is actually called",
      "verified_description": "what it actually does, based on search results",
      "claimed_vs_actual": "matches|differs|unverifiable",
      "correction": "null if matches, or the accurate description if differs",
      "source_url": "URL of the source that confirms this"
    }
  ],
  "verified_statistics": [
    {
      "claim": "the original statistic as stated",
      "attribution": "who it's attributed to",
      "status": "confirmed|different_number|different_context|unverifiable|fabricated",
      "actual_value": "the real number if different, or same if confirmed",
      "actual_context": "what the stat actually measures",
      "source_url": "URL"
    }
  ],
  "additional_relevant_data": [
    {
      "competitor_or_source": "string",
      "insight": "string — verified fact relevant to this audit",
      "source_url": "URL"
    }
  ]
}

RULES:
- Use web search for EVERY claim. Do not rely on training data alone.
- If you cannot verify a claim after searching, mark it "unverifiable" — do not guess.
- If the real number differs from the claimed number, provide BOTH.
- Include source URLs for everything you verify.
- Do not editorialize. Just report what you find.
```

5. Click outside the Inputs field to confirm.

## Step 3.3: Create the Escape Compose Actions

WHERE AM I?: Power Automate > Flow Editor > Directly below Research_User_Prompt_1

Your existing flow uses a replace chain pattern to escape prompt text for safe JSON embedding. We need the same pattern for the research prompts.

1. Click + below Research_User_Prompt_1 → Compose → Rename to: Escape_Research_System_Prompt

2. In the Inputs field, click the Expression tab (fx) and paste:

```
replace(replace(replace(replace(outputs('Research_System_Prompt'), '\', '\\'), '"', '\"'), decodeUriComponent('%0A'), '\n'), decodeUriComponent('%0D'), '')
```

Click OK.

3. Click + below Escape_Research_System_Prompt → Compose → Rename to: Escape_Research_User_Prompt_1

4. In the Inputs field, click the Expression tab (fx) and paste:

```
replace(replace(replace(replace(outputs('Research_User_Prompt_1'), '\', '\\'), '"', '\"'), decodeUriComponent('%0A'), '\n'), decodeUriComponent('%0D'), '')
```

Click OK.

> **BEGINNER TIP**: This replace chain does four things in order: (1) escapes backslashes, (2) escapes double quotes, (3) replaces newlines with literal `\n`, (4) removes carriage returns. Without this, the JSON body will break when the prompt text contains quotes or newlines. This is the exact same pattern used by your existing Escape_Loop_System_Prompt and Escape_HTML_System_Prompt actions.

## Step 3.4: Create the Research_API_Call_1 HTTP Action

WHERE AM I?: Power Automate > Flow Editor > Directly below Escape_Research_User_Prompt_1

1. Click + → HTTP (premium connector, blue globe icon).

2. Configure:
   - Method: POST
   - URI: `https://api.anthropic.com/v1/messages`
   - Headers (add 3):
     - `x-api-key`: Click dynamic content (lightning bolt) → select the output from your existing Get_Anthropic_Key action. Use the exact same reference your HTTP_Loop_Vision action uses.
     - `anthropic-version`: `2023-06-01`
     - `content-type`: `application/json`
   - Body: Click the Expression tab (fx) and paste:

```
concat('{"model":"claude-sonnet-4-6","max_tokens":4096,"temperature":0.1,"tools":[{"type":"web_search_20250305","name":"web_search","max_uses":8}],"system":"', outputs('Escape_Research_System_Prompt'), '","messages":[{"role":"user","content":"', outputs('Escape_Research_User_Prompt_1'), '"}]}')
```

Click OK.

> **CRITICAL**: This uses the same manual JSON string construction pattern as your existing Loop_Payload and Build_HTML_Request actions. The escaped prompt outputs are inserted directly into the JSON string. The `max_uses: 8` limits this call to 8 web searches, keeping it well under the 120-second hard timeout.

3. Click the three dots (...) → Settings:
   - Security → Secure Inputs: On → Secure Outputs: On
   - Networking → Timeout: PT120S
   - Click Done.

4. Rename to: Research_API_Call_1

> **WATCH OUT**: If you get a 400 error about invalid JSON, the most common cause is unescaped characters in the prompt. Verify that Escape_Research_System_Prompt and Escape_Research_User_Prompt_1 produce properly escaped strings by checking their outputs in a test run.

## Step 3.5: Extract the First Research Output

WHERE AM I?: Power Automate > Flow Editor > Directly below Research_API_Call_1

1. Click + → Compose → Rename to: Extract_Research_1

2. In the Inputs field, click the Expression tab (fx) and paste:

```
last(body('Research_API_Call_1')?['content'])?['text']
```

Click OK.

> **BEGINNER TIP**: The Anthropic API response `content` array contains multiple blocks when the web search tool is used: `server_tool_use` blocks (search requests), `web_search_tool_result` blocks (search results), and `text` blocks (Claude's reasoning and final answer). The `last()` function grabs the last element, which is the final JSON output. If during testing you find the JSON is not the last element, check the full content array in the run history and adjust the index.

# PHASE 4: Update the Loop System Prompt (Grounded Citation Rules)

## Step 4.1: Add Grounded Citation Rules to Loop_System_Prompt

WHERE AM I?: Power Automate > Flow Editor > Loop_System_Prompt (existing Compose action)

1. Click on your existing Loop_System_Prompt Compose action to expand it.

2. Scroll to the very end of the prompt text. Find the section that begins with `CRITICAL RULES:`. It currently reads:

```
CRITICAL RULES:
- "filename" MUST be the EXACT original filename from the user prompt.
- Every finding references specific visible UI elements.
- Never fabricate elements not visible in the screenshot.
- When evidence is ambiguous, state the ambiguity and qualify confidence.
```

3. Place your cursor directly ABOVE the `CRITICAL RULES:` line. Paste the following new section:

```
GROUNDED CITATION RULES — MANDATORY:
You have been provided VERIFIED RESEARCH CONTEXT below the screenshot. This contains confirmed competitor features, verified statistics, and corrected claims — all backed by web research with source URLs.

- You may ONLY cite statistics that appear in the verified research context. Do NOT invent percentages.
- If the verified research shows a claimed statistic is wrong or unverifiable, use the corrected value or omit it entirely.
- If the verified research shows a competitor feature works differently than expected, describe what it ACTUALLY does.
- If no verified data exists for a claim you want to make, write "Industry best practice suggests..." with NO specific percentage.
- NEVER fabricate a statistic. NEVER attribute a number to a company without it appearing in the verified research.
- You MAY cite the general industry data provided in your system prompt (e.g., Capgemini, BCG, Pattern Group) — but only numbers that also appear confirmed in the research context.
```

4. Now update the CRITICAL RULES section. Add one new bullet. It should now read:

```
CRITICAL RULES:
- "filename" MUST be the EXACT original filename from the user prompt.
- Every finding references specific visible UI elements.
- Never fabricate elements not visible in the screenshot.
- Never fabricate statistics not in the verified research context.
