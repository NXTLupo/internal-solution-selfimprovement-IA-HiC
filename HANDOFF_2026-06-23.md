## 2. What changed in commit `b573f05b1` (29 files, +2433/-323)

### A. Chat UX overhaul — non-hashtag Analyst Desk + Designer Desk (gemini-3.5-flash)
**Problem:** plain chat replies rendered as an ugly 11px `pre-wrap` text wall; the renderer
(`cleanResponseText`) actively STRIPPED `##`/`**`/`*`; the model formats inconsistently.
- **NEW `components/ChatProse.tsx`** — renders a chat reply as structured prose (h2/h3, bullets,
  numbered lists, blockquote, bold/italic/code) from a safe Markdown subset. The load-bearing piece
  is `normalizeMarkdown()`: Gemini 3.5 Flash emits the markers (`## `, `- `, `> `, `N.`) WITHOUT
  newlines, so the normalizer **reconstructs block boundaries from inline markers** — breaks headers
  onto their own line (preceding char must not be `#`), splits a "Title Bodysentence" header at the
  earliest sensible boundary (protecting a leading `N.`), breaks inline dash + numbered list items,
  and promotes runs of `**Label:**` lead-ins into bullets using **sentinel masking** (so the
  single-star italic pattern never matches inside a double-star bold). No regex lookbehind (it
  SyntaxErrors at module load on older engines and blanks the app).
- **`forceOrderedList`** — when the user names a count ("10 steps", "top 5 ways"; detected in
  `CorpusChatPanel` by scanning the preceding user turn), ChatProse collapses ALL list items into
  ONE consistently-numbered ordered list (01..N), regardless of how the flaky model formatted it.
  This fixes "the numbers were inconsistently applied".
- **Spacing redesign** — assistant replies render in a roomy GOLD-like card (16x18 padding, white
  surface, 1px `#E4E4DC` border + 3px brand-accent left rule + 2px radius); message-list gap 10→16
  on a `#FAFAF7` surface; ChatProse uses a `ROW` rhythm unit. Applied to BOTH chats
  (`CorpusChatPanel.tsx` + `design-desk/DesignDeskChat.tsx`).
- **Latency** — the plain-chat agentic tool-loop (`callGemini`) was burning all 5 iterations
  re-fetching the wiki (`fetch_wiki_articles` limit 30-60) even though the manifest corpus is
  already injected, at `maxOutputTokens: 65536` → 276s. Fix: cap the gemini loop at
  `min(MAX_TOOL_ITER, 3)`, drop the output cap to 16384, and the DEFAULT-chat prompt now says
  "answer from the MANIFEST-SELECTED evidence already injected (anti-RAG); fetch at most once".
  ~3.3x faster (276s → ~83s). NOTE: "Validating citations…" in the UI is a **cosmetic** rotating
  label (`CorpusChatPanel.tsx:211`), not real work.
- DEFAULT-chat prompt also got: HONOR EXPLICIT COUNTS + a prescriptive structured-formatting recipe.
- **NEW skill** `.claude/skills/analyst-chat-formatter/SKILL.md` (the rich-text contract the user
  asked for).

   long posts). The durable fix is upstream: rebalance collection volume against the selected source
   packs + tighten the retrieval cap. Documented in

## 4. Gotchas the next person will hit

- **Gemini 3.5 Flash formats the same request differently every run** (3 phase-headers / 10 bullets
  / inline numbers). Renderer normalization alone is whack-a-mole — enforce structure
  deterministically when the user names a count; don't trust the model's whitespace.
- **The chat #slides path is its OWN finalizer** in `corpusChatService.sendChatMessage` — separate
  from the geminiService deliverable path. Fixes to one don't reach the other.
- **`removeMetaNarration` bails on `:::slide`** and **`stripProcessReferences` greedy `.*` eats
  single-line slide JSON** — that's why the chat scrub had to be bounded/fence-aware.
- **SlideCanvas renders React components from `goldPreviews.tsx`**, NOT `web.tsx` (the web.tsx theme
  renderers are legacy/unused). `check-template-parity.mjs` reads the `SlideTemplate` union with a

Markdown parser against each new shape Flash produced, instead of recognizing early that the model's
run-to-run formatting variance demanded a deterministic renderer-side contract. The lesson, now in
